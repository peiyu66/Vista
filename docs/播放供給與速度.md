# 現行播放供給與速度

Build104的已採用累積基底。接受及驗證界線統一見 [已驗收基底](已驗收基底.md)，本頁說明目前程式契約，不重新批准候選或展開效能研究。

## 速度與有界恢復

速度範圍1～5×、每次0.5×；不支援快速播放的item上限2×，有支援才開放超過2×。暫停中改速不自行播放，seek保留選定倍率，新片從1×開始。UI同時區分選定速度與實際觀察，缺少資料不填造。

等待降速使用0.5秒有效等待觀察、3秒冷卻。低供幀的rolling觀察保留0.3秒；獨立gap支線要求0.2秒沒有前進新幀、至少6次真poll及足夠clock前進。selected／effective至少2.5×才採每步減0.5、最低2×；每步重新確認實際倍率與clock，再建立新完整窗。健康參考、觀察新鮮度、pause／seek／背景／來源保護仍適用，不把0.2秒當畫面恢復保證。

有界停滯恢復以ready、active、明確播放意圖、先前clock／PTS進展、足夠buffer和可確認idle來源為必要條件。新鮮觀察下clock／PTS與idle連續停滯一秒才取得資格；不把未知來源或取消未排空視為idle。共用episode額度、attempt間隔／上限及15秒active budget，同圈最多一個play命令，使用最新選定速度。命令、bytes或transport轉playing不算成功，需clock及兩個嚴格前進PTS並核對source epoch。pause／seek／inactive／換片／來源失效仍可阻止後續動作，不新增seek、flush、rebuild或無界重試。

背景維持暫停，回前景不自動播放。倍速根因研究已暫結，已知停頓保留於待解及匿名有界診斷，不宣稱原問題全部消失。

## 來源與資料保留

單次需求上限2 MiB。主列表既有SMB factory使用播放專用持續唯讀handle、恢復wrapper和prefetch wrapper；普通本機、Demo及舊入口沒有因104新增ring包裝。

持續handle採READ／WRITE／DELETE分享及OPEN，只有明確unsupported CREATE回應可降級既有讀取；權限或一般錯誤不能觸發降級。每handle序列positioned reads，依協商尺寸分塊，短正數繼續、零長度到EOF。停止先拒新工作，等待真實操作排空後close；取消不保證立即中止底層blocking call或遠端handle已消失。來源恢復維持既有一次完整range重試及身分核對，詳見 [播放中斷恢復](播放中斷恢復.md) 與 [依賴修補](../DependencyPatches/AMSMB2-4.0.3-persistent-readonly-handle.md)。

ring arena固定160 MiB，最多4 MiB前向目標，單筆2 MiB，維持單序列及最多兩次順序預讀，不新增平行SMB。新資料確實提交時才逐步覆寫舊資料；同來源有效的已完成資料可跨普通pause、seek及單筆取消保留，取消的請求不回覆、不復活。索引最多1024項，另有在途、快照及回覆成本，160 MiB不是整個程序的記憶體上限。

背景保留arena但隔離禁止直接命中，前景首筆需求須fresh metadata核對，且與後續讀取共用原恢復預算。新source epoch、確認身分失效、換片、停止或記憶體壓力清除；metadata不足可普通讀取但不能驗證或重新填入舊隔離arena。metadata指紋不是不可變快照。

104只擴充seek期間正式需求成功資料的保留資格：同generation/token/epoch且仍有效才能入庫，不新增前向credit或預讀。具體互動見 [跳轉互動](跳轉互動.md)。

## 診斷與限制

保留前向需求、範圍／等待、來源供給、控制器及播放意圖等匿名數值診斷。一般記錄單筆8 KiB、pending8筆、每檔262144 bytes／每lane4檔；wait journal有界1 MiB。emitted不等於已耐久寫入。不記片名、私人路徑、帳號或任意底層error文字；有界紀錄與歷史觀察不構成根因證明。

此頁不採用雙區預讀、取消排隊或MKV策略，也不把歷史容量／效能觀察稱成本次新測。
