# 魚眼貼圖重用

2026-11-07：此處已接受的魚眼runtime原樣保留於目前乾淨來源基底，未加入新的renderer恢復策略。後續來源整合與驗收界線見 [已驗收基底](已驗收基底.md)；下方Build42未推送／候選敘述為當時歷史，不表示目前所有功能狀態。

2026-11-06。使用者回報一般影片切換魚眼模式時嚴重卡頓，不是要求辨識特殊魚眼素材；Build40 實機回報卡頓已解決。本次將同一份魚眼程式接到 [Build38 已驗收基底](已驗收基底.md)，排除 Build39／40 的 SMB timeout 實驗。來源建置號為 42，未安裝、未簽署發布。

**目前只保留獨立本地候選，未推送 main、未建立 release。** 排除 SMB 實驗後的組合並非已上機的 Build40，也不含另一份已安裝 Build41 的仰角補償，需另完成整體驗收後才能按授權推進。Build42 僅識別這份候選，不表示已驗收或發布。

## 已採用的修改

- 保留 AVPlayer 原生輸出與產品 ShaderGraph。魚眼模式直接接收 DecodedVideoFrame，不先在主執行緒逐幀製作 CGImage。
- 對明確 BT.709 primaries／transfer、無方向變換的 SDR 影格，以 Core Image 讀取實際 CVPixelBuffer，再更新持續存在的 LowLevelTexture。每個設定／播放 session／尺寸組合只建立一次每眼 TextureResource，不逐幀重建貼圖。
- 一個處理工作加一個最新待處理影格，避免無界排隊；切換、停止與新播放 session 使舊結果失效。來源影格與貼圖持有到 Metal command 完成。
- 停止系統呈現器改為冪等操作，避免魚眼路徑每幀重複 flush。未改 SMB 讀取、AVPlayer 解碼選擇或跳轉策略。
- 未符合條件或 GPU 更新失敗時保留原 CGImage／雙貼圖回退。取消旗標 VISTA_FISHEYE_GPU_CANDIDATE 可停用 GPU 路徑；完整基底回退可檢出前一筆 Build38 基底提交，不要對共享 main 強制回退。

## 驗證與界線

魚眼程式與已安裝 Build40 的 VRRenderer、VRPresentation 逐位元相同。本次重新建置與合成 UI 檢查的結果記錄於下方，不能把沿用的實機驗收說成 Build42 重新上機。

先前同 GPU 路徑的離屏比對使用 AVPlayer 實際輸出的 H.264 8-bit 與 HEVC Main10 SDR 壓縮 bi-planar 像素，不假設固定 BGRA／YCbCr 格式。對原雙貼圖畫面的平均 RGB 誤差分別約 0.258／255、0.011／255，最大 2／255；普通模式、停止後清畫面與重新播放通過。這只證明該合成 SDR 樣本的相容性，不能代表 HDR 或真實 8K 吞吐。

HDR／未標記色彩／非 identity 方向變換仍走原回退；本路徑輸出是 8-bit sRGB 貼圖，接受 10-bit SDR 輸入不等於保留完整 10-bit 或 HDR／EDR。真雙眼光學效果、各種高解析影片的長時效能未全面驗證。摘戴後退出 App 與部分跳轉等待仍未解決，不能將此次魚眼驗收延伸為它們已修復。

## 最小重驗方法

主要工程預設啟用原生播放與魚眼旗標。Debug 使用獨立魚眼候選 bundle ID，Release 保持既定產品 ID。核心合成檢查可使用：

```sh
swift test --no-parallel --filter 'NativePlaybackSessionTests|VRFisheyeTests|VRProjectionTests|PlaybackMetricsTests|PlaybackLogTests'
xcodebuild -project VistaBrowser.xcodeproj -scheme VistaBrowser \
  -configuration Release -destination 'generic/platform=visionOS' \
  CODE_SIGNING_ALLOWED=NO build
```

在專用 visionOS Simulator 執行 VistaUITests/testFisheyeGPUCandidateSwitchAndStop，附加以下編譯條件：

```text
DEBUG VISTA_SYSTEM_VIDEO_EXPERIMENT VISTA_NATIVE_PLAYER_EXPERIMENT VISTA_ANON_IO_EXPERIMENT VISTA_FISHEYE_GPU_CANDIDATE VISTA_DIAGNOSTIC_UI
```

測試只開專案自造 FisheyeSDR.mp4（512×256、30 秒 H.264、limited-range BT.709），依序檢查普通 180° → 魚眼 GPU → 普通 180° → 停止返回。診斷 UI 只供測試辨識路徑，未列入 Release。沒有連 NAS、讀取私人影片或操作實體裝置。

UI 測試 target 與 App 的播放旗標已同步。需要診斷畫面的測試於未 opt-in 時明確 skip，舊模擬器軟解診斷不套用到 AVPlayer。這不是宣稱整套 UI 測試已通過。封存的 SyntheticControls.mp4 是 120 秒；舊 GenerateSyntheticMovie.swift 的 --controls 只產生 30 秒，不能用它直接覆寫封存檔而仍期待 02:00，本次未改生成器或擴大重製工作。
