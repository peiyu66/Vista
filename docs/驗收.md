# 驗收規劃

日期：2026-11-03。以下是完整產品驗收項目；初期實測結果見本頁下方，不代表所有能力均已完成。

| 項目 | 驗收證據要求 |
| --- | --- |
| 本機／SMB | 可開啟授權檔案；分別測 SMB 2/3 與經 Tailscale 連 Mac；記錄系統版本、網路條件與失敗處理 |
| 大量目錄 | 數千檔案情境的載入耗時、操作延遲與記憶體；門檻需先定義，不能只以能列出檔案判定通過 |
| 硬體解碼 | 逐項記錄容器、codec、profile、解析度、幀率與實際解碼路徑；不支援者明確拒絕且無軟解回退 |
| VR 格式 | SBS、上下、180、360、魚眼的代表組合；自動判斷錯誤可手動修正並於重新開啟後保留 |
| 影片識別 | 不同目錄同名片不誤用設定；持久化與識別方案確定後補齊案例 |
| 初始視角 | 坐姿、躺姿與側躺開檔時的基準視角；開檔後不持續自動改變校準，手動調整有效 |
| 憑證與安全 | 系統自動填入及伺服器配對實測結果、憑證不外洩、保留 SMB 安全功能；不可用時記錄限制 |
| 範圍 | 初期介面無 Finder 標籤及改名、搬移、複製、刪除功能 |
| 發布 | 第三方與素材授權、Apple 規範、隱私及 App Store 資料依發布時要求另行確認 |

實測需分開記錄原型、模擬器與 Vision Pro 裝置結果。不得將模擬器通過當成實機硬解、姿態或效能驗收。初期已執行模擬器建置與測試，尚未執行實機操作。

更新驗證：獨立 visionOS 26.1 模擬器通過 2 項 UI 測試（0 failures，39.860 秒），包含空表單按鈕回饋、密碼欄 Return 驗證及既有完整兩欄／預覽返回流程。沒有在回歸測試輸入私人帳密或連接真實分享；原使用者 session 保持不變。

## 2026-11-03 視窗與版面

原 `WindowGroup` 已使用可調整的 automatic／contentMinSize 策略，1000 × 680 是初始尺寸。本次明確指定 contentMinSize，最小 800 × 560 維持不變。原生角落拖曳未由此次 Device Hub 指標自動化成功觸發，不能列為手勢實測通過。

原始尺寸設定的獨立模擬器回歸 2 項通過。另在暫存專案副本將內容固定為 800 × 560 及 1400 × 900，加入 GeometryReader 實際內容尺寸斷言與返回／離開／目錄列可點擊檢查，執行兩欄及預覽返回測試；此為指定尺寸版面測試，不替代動態拖曳驗收。大尺寸亦觀察到兩欄及控制未重疊。最初大尺寸斷言因 SwiftUI 顯示千分位「1,400」而失敗，非版面尺寸錯誤；修正測試格式後，曾遇 runner 沿用舊 800 × 560 斷言；改用獨立暫存 runner 識別後重驗通過。800 × 560 與 1400 × 900 最終各 1 項測試通過，證據為 `/tmp/VistaResize800Measured.xcresult` 與 `/tmp/VistaResize1400FreshRunner.xcresult`。測試副本及幾何標記不納入產品。
