# 跳轉互動與資料保留

Build104以已接受的103為底，保留其完整UI與播放基底。使用者已回報跳轉恢復順暢；本次沒有受控實機延遲數值，因此不宣稱固定提速倍數或全部情境已修好。

## 滑桿真正改值才提交

`PlaybackScrubInteraction` 以owner識別與真正value變化追蹤一次互動；純touch不seek。value setter先於begin仍可正確記錄，同owner重複begin不清掉已改值狀態，移動再回原點仍提交，最小非零改值也不吞掉。end只消耗一次，重複end不重送；換player／generation同步丟棄過期互動。

普通播放入口的有效改值即使前次seek preparing仍可提交；沉浸入口保留原enabled／active／stopping／同player gate。沒有改Native或PlaybackController的seek語義，也沒有取消排隊策略。

## seek期間正式需求保留

seek會撤銷舊預讀及其重啟資格；已需要的正式需求依原規則完成。新 `retainsSeekDemand` 只讓同generation、token、source epoch且仍有效的正式讀取payload保留至history，不產生預讀credit、不自行啟動預讀。背景、停止、換片、來源失效與記憶體壓力保護保持。

此路徑僅在主列表既有SMB wrapper生效；普通本機／Demo／舊入口沒有新加wrapper。滑桿改善可作用其既有UI入口，不能把ring效果擴張成所有來源的量測結論。

## UI與驗證界線

保留title3完整單行／caption完整折行、進度duration字體對應的右保留區與16pt內縮、水平角度header間距、純顯示尺及四向15°按鈕。沒有尺drag、上下倍速手勢或104之後的狀態清理。

精確35項／11組集合涵蓋互動、Native/controller提交交界、seek保留、cached-range一次恢復、純Data整合、角度與進度；它不是SwiftUI實機+SMB端到端重播。UI只編譯，實際版面與跳轉接受來自使用者的已安裝版本。正式工作樹結果見 [baseline](../tools/Build104AcceptedBaseline.json)。
