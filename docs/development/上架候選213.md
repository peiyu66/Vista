# 1.0（213）上架候選核對

213 接續正式 211 與已測試的 212／213。使用者在測試 213 後要求以該版建置 Release、上傳 Connect 並同步 GitHub，停在提交審查之前。版本維持 1.0（213），沒有新增版號、安裝或啟動裝置。

## 受控差異

- 拖移把手維持 44 點布局，interaction 與 hover 的 Capsule 各內縮 4 點，實際目標直徑 36 點。既有 DragGesture、優先級、捲動、排序和保存語義不變。使用者表示縮小沒有改善且不想放大；依其指定 213 保留目前設定，不宣稱捏合問題已修復。
- DEBUG／VISTA_DIAGNOSTICS 下被動記錄已送達的開始、狀態、結束、排序及捲動，匿名且有容量限制；Release 排除記錄器和呼叫點。未新增辨識器、眼睛追蹤或手部追蹤權限。未送達的物理捏合和眼睛焦點不可觀測，不能據此計算完整成功率。
- 中文內嵌隱私與公開網站改連 GitHub 中文隱私頁；英文保留英文目的地。About 頁僅新增兩個測試識別碼，既有入口、版本位置、24 點底部間距、首頁、使用說明與聲明連結保留。
- UI-test target 移除重複連入 App 原生庫的 linker flags，App target 的原生輸入及播放策略未改。沒有納入實驗用 UI 自動化測試。
- Home 圖示資產未修改。使用者回報圖示已恢復，原因未知，不能歸功於本版修正。

## 測試與限制

`tools/Store213/verify.py` 核對凍結來源及既有原生產物；`verify_scope.py` 精確比對基線 UI，排除未授權的播放或手勢改動。`test_input_log.py` 執行實際 recorder／writer，`test_all_writers.py` 執行完整 VistaCore／VistaMedia 的主機寫入器。兩種配置應分別確認 Diagnostic 寫檔、Release 不新增日誌且舊檔不變。

既有 213 Diagnostic 實機紀錄有 55 段完整已送達拖移，全部正常結束；這不代表只嘗試了 55 次，也不代表未收到的捏合沒有失敗。原始裝置紀錄、裝置識別碼、簽署資料和私人路徑不納入公開 repository。這次 Release 不新增完整實機執行證據；207 乾淨容器播放後無自製日誌的既有證據及其限制仍見[日誌分流](日誌建置分流.md)。

## 上傳與待確認事項

Release archive 成功；Diagnostic 手勢 writer 產生 JSONL，Release 不產生新檔並保留既有檔案；完整 VistaCore／VistaMedia 主機測試分別產生 6／0 個檔案。中英文各 450 個 Bundle lookup、433 個 literal 鍵、各 7 個隱私標題與 5 個連結及五份授權原文檢查通過。成品沒有手勢 probe／Flow writer 符號，資源與凍結來源相符。

App Store 分發簽章通過 strict／deep 核驗，get-task-allow 關閉，主程式 43 個及 AMSMB2 35 個編譯 section 與同一 archive 一致。Xcode 回報上傳成功及 Apple 開始處理；Connect 上傳紀錄已顯示 1.0（213）「處理中」，最終處理和草稿關聯仍待核實，不等同已送審。沒有提交 App Review。既有出口合規技術依賴沒有改變；中國 ICP 適用性、隱私最終發佈同意及送審完整驗證的原有界線見[211 核對](上架候選211.md)，不把上傳成功當成已完成全部合規或審查。
