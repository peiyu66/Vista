# 1.0（211）上架候選核對

211 延續 [210](上架候選210.md) 的播放策略、內建聲明與 Release／Diagnostic 日誌分流。使用者要求修正雙語隱私標題、增加關於頁首頁連結，建置及安裝 211 後上傳同一 archive 的分發簽署產物；尚未授權提交審查。本紀錄區分程式驗證、上傳與法規待辦，不代表已上架或全面合規。

## 已整合及驗證

- 隱私頁原先以 inline-only Markdown 解析整段文字，未把 ATX 標題轉成 SwiftUI 標題。現在僅對內建隱私文件解析標題與段落，呈現對應字級及輔助使用標題特徵；中英文各驗證 7 個標題、5 個 HTTP(S) 連結。其他五份授權文件保留逐字內容及空白。
- 關於頁的「Vista 首頁」／「Vista Home」位於使用說明上方，直接開啟同語言公開首頁。原左下角入口、版本位置、底部 24 點留白、Apple Material 及其他連結不變。
- 兩語各 450 個實際 Bundle lookup、433 個 literal 呼叫鍵與格式參數核對通過。Release archive 成功，內建文字與來源一致，編譯後本地化資源語意一致。
- 211 的 35 個產品來源、18 個原生來源與 2 個原生產物列入 baseline；原生來源及產物與 210 相同。Release 未含診斷旗標與 Flow writer 符號。日誌執行證據沿用未改變實作的既有測試，並非本次重新完整播放實測。
- 開發簽署、就地安裝及裝置讀回 1.0（211）已完成，未啟動、卸載或清除資料。代理沒有完成本次頭盔內畫面／操作驗收。
- App Store 分發簽章驗證通過，主程式 43 個及 AMSMB2 35 個編譯 section 與同一 archive 相符；沒有為上傳重新編譯或增加版號。

重跑來源核對：`python3 tools/Store211/verify.py`。內建聲明測試：`python3 tools/Store211/check_notices.py`。本地化測試：`python3 tools/Store208/check_resources.py`。`tools/Store211/baseline.json` 保留來源與未簽署二進位雜湊，不包含個人裝置、憑證或帳號資料。

## Connect 核對結果

同一 211 archive 已成功上傳，Connect 顯示二進位「已驗證」。中英文商店描述均已修正為使用者選擇投影與排列並逐片保存，移除自動選擇魚眼的錯誤承諾。公開中英文首頁、使用說明、第三方聲明及隱私來源共八份與 GitHub main 一致；支援／行銷／隱私 URL、版權及既存 review demo 與聯絡欄位已核對。未改動截圖、發行方式或地區。

211 加密問卷已依成品與來源選擇「除 Apple 作業系統外使用其他標準加密演算法」，法國發佈選「否」，符合原先排除法國的地區設定。儲存後 TestFlight 狀態由「缺少出口合規資訊」變成「準備提交」，此流程未要求上傳加密文件。211 已關聯至 1.0 草稿；沒有點選新增以供審查或提交審查。

加密判斷包含 AMSMB2／libsmb2 的 AES-CCM、AES-CMAC、NTLM 與雜湊實作；AES 基元呼叫 CommonCrypto，不能因此把整個套件當成只有作業系統加密。211 framework 符號確認上述實作包含於成品。主程式使用 CryptoKit 的 SHA-256／HMAC、CommonCrypto 與系統 Security；原生 VLC 組態停用 GnuTLS／libgcrypt，成品未發現對其或 OpenSSL／mbedTLS 的連結或相關符號。符號檢查與來源／建置組態互相對照，不以單獨缺少符號作為不存在加密的證明。

未修改已上傳二進位的 Info.plist，也不將問卷文案「未含加密」當成 Vista 不使用加密的事實。Apple 不要求上傳文件，與美國出口分類／年度自我分類報告是否適用，是不同問題；後者的初步分類見下節，不能依 Apple 問卷直接推論。依據：[Apple 加密文件表](https://developer.apple.com/help/app-store-connect/reference/app-information/export-compliance-documentation-for-encryption)、[Apple 加密出口說明](https://developer.apple.com/documentation/Security/complying-with-encryption-export-regulations)。

隱私頁可見「不收集資料」及既存 URL。已打開最後發佈確認，Apple 要求同意回覆正確、符合審查規範及法律，並在資料處理改變時立即更新。此持續義務的最後同意仍待當次確認；本輪取消對話，沒有按最終「發佈」。未執行提交審查的最終驗證，不能排除 Connect 仍要求其他必填資訊。正式送審須等待使用者確認；既有「審核通過後自動發佈」設定未變更。


## 年度自我分類報告的初步判讀

核對現行 [§740.17(e)(3)](https://www.bis.gov/regulations/ear/740) 及 [BIS 2021 改制表](https://www.bis.gov/media/documents/table-changes-enc-wa2019-rule-final-version.pdf)：一般符合 (b)(1) 的 mass-market 5D992.c 成品軟體已不再要求年度 self-classification report；特定硬體元件的 executable software 及仍列 5x002 的情況不同。不能沿用部分 BIS 指南頁「所有 (b)(1) 都須年度申報」的概括敘述，也不能把每個 App 可執行檔都套入此處對 executable software 的狹義定義。

本次對象是完整 Vista App，不是獨立出售的加密元件或硬體韌體。包內 AMSMB2 使用公開的標準演算法；沒有自訂加密、使用者更換加密演算法的介面、政府客製、VPN／路由基礎設施、滲透／鑑識或其他 (b)(2)／(b)(3) 接線。程式與建置依賴可追溯，不能因包內有第三方函式庫而直接認定成品要申報。

[Category 5 Part 2 Note 3](https://www.bis.gov/regulations/ear/774) 的一般市場條件，對 211 的比對如下：

- 已規劃透過 App Store 向一般使用者提供，功能公開、免 Vista 帳號及訂閱；尚未上架，這是分發計畫而非已公開銷售的事實。
- 安裝使用不需供應者進行客製或改演算法；輸入自己的 SMB 帳密與來源不會修改加密實作。
- 加密程式與技術資料已保留、可提供；若主管機關要求時實際提供資料的義務，仍由出口者承擔，不替本人作額外承諾。

因此，按目前一般市場完整 App 的分發計畫，5D992.c／(b)(1) 是有依據的初步分類路徑，未發現要求 211 年度申報的技術特徵。不把年度報告列成已確定的上架阻礙，也未代為申報或宣稱已取得 BIS 裁定。如果分發方式、加密功能或實際用途改變，須重新判讀。

另有較前階段的排除依據：[BIS 對娛樂用途加密的說明](https://www.bis.gov/learn-support/encryption-controls/cryptography-for-data-confidentiality) 包含專用影音播放。Vista 的加密用於媒體讀取、認證與完整性，符合此方向；本次不僅憑播放器名稱便直接宣告 EAR99，也不把完整 App 的判讀擴張到獨立分發的開發套件。非美國個人身分本身不是自動豁免。

中國功能聲明與網路資料流的進一步比對見[資料處理核對](資料處理核對.md)。Connect 恢復登入後已完成上述兩項功能聲明，隱私最終發佈仍待確認。
