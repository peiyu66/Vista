## 實際行為

H.264／HEVC 仍依原壓縮輸入順序呼叫 VideoToolbox；前一次 API 返回後，未收到 callback 的輸入最多三筆。成功、失敗及丟棄 callback 都釋放名額，callback 早於 API 返回是正常情況。直接錯誤沒有 callback 時只釋放一次。沒有 100 ms 或其他到期旁通；等待中的短條件輪詢只觀察實際 flush／退出，不放寬名額。原有 VideoToolbox completion fence、session 代次及 pacer 保留。

只有原路徑已判為不輸出的 HEVC preroll，且實際 parser／活動 SPS、VPS 證明為單層、單時間層、單一完整 TRAIL_N slice，才省略硬解提交。格式未就緒、設定改變、Dolby Vision、非完整單 slice 等情況沿用原解碼。不能只憑 NAL 名稱省略一般影格或參考影格。

省略輸入仍執行原有 DPB 與日期更新，並等先前 callback 完成其 metadata／pacer 工作；不建立假 callback、不消耗硬解名額、不逐張 drain。必要參考鏈、原有畫面排序及同步條件保持。

上述功能在 Release 與 Diagnostic 都生效。診斷只透過既有有界 scalar Flow 通道記錄，不移入實驗版的來源雜湊記錄器，不新增檔案寫入器；Release 不啟動 Flow，維持 [日誌建置分流](日誌建置分流.md)。本次重新編譯最新 `MKVProducer.cpp`，沒有沿用分流前 object。
