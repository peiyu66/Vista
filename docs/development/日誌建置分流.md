# 日誌建置分流

2026-11-17。同一套原始碼，不依下載來源猜測，不提供上架版的執行期開關。

- `Release`：關閉 Vista 自製診斷檔案及 Lifecycle OSLog；不啟動 Flow trace；VLC 採 quiet 並消化 logger 回呼；MKV producer 不開診斷 ledger。錯誤提示、必要播放狀態、降速判斷、使用者設定與影片暫存仍保留。
- `Diagnostic`：沿用 Release 最佳化，Swift / C 同時啟用 `VISTA_DIAGNOSTICS`，保留原有詳盡日誌。用 Xcode 自行建置，不上傳商店。
- `Debug`：同樣開啟診斷，供開發除錯。效能對照請用 Diagnostic 而非 Debug。

App Store Archive 保持 Release。範例：

```sh
xcodebuild -project VistaBrowser.xcodeproj -scheme VistaBrowser -configuration Release -sdk xros build
xcodebuild -project VistaBrowser.xcodeproj -scheme VistaBrowser -configuration Diagnostic -sdk xros build
```

依既有 NativeBuild 流程準備原生產物。更新 producer 來源後必須重建 `MKVProducer.o`，不能沿用關閉 ledger 前的舊 object。使用者端不可藉偏好或 launch argument 開啟 Release 日誌。

## 驗證與界線

`python3 tools/Logging/check.py` 對實際 lifecycle 類別及抽取的 playback/controller writer 做最佳化主機測試，確認 Release 不新增檔案、Diagnostic 仍寫檔、舊檔不刪除。測試中的 record 是最小替身，不代替完整裝置播放。

`python3 tools/LoggingPolicy/native_event_test.py` 對實際 producer event 函式做 ASan/UBSan 開關測試。兩個 xros 配置另須完整編譯。

不關閉 Apple 系統本身的 crash 或診斷；第三方直接繞過 LibVLC logger 的輸出未有完整執行期保證。舊版已留下的日誌不因更新自動刪除。必要來源設定、Keychain、格式偏好及播放暫存不是日誌，不在此功能刪除。

關 Flow 後，renderer 的 blocked-frame 判別使用既有物件身分 fallback；它仍阻止重送同一個 frame，未修改播放策略。本次主機驗證不代替真機音畫／長時間播放測試。

本輪驗證：Release／Diagnostic unsigned xros 建置均成功；最佳化主機雙模式 writer 測試、renderer 身分 fallback 測試、producer ASan/UBSan、255 項既有直接降速恢復政策斷言、30 項 lifecycle 回歸測試通過。記憶體中仍可能保留診斷相關計算，未宣稱零額外 CPU 成本。可重現來源雜湊見 `tools/Logging/baseline.json`。未安裝或啟動實體裝置。
